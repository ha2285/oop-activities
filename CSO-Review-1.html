How a computer sees your program

No background needed. Each tab covers one page of the lecture notes: the main idea, an everyday comparison, small experiments you can click, the usual mistakes, and three quick questions.

A number is a count. A base is a way of writing it down.

Twelve apples are twelve apples. We can write that count as 12 in decimal, 1100 in binary or C in hexadecimal. The count never changes, only the notation.

Think of it like

A car's odometer. Each wheel shows 0 to 9. When a wheel passes 9 it rolls back to 0 and nudges the wheel on its left up by one. A binary odometer works the same way, except each wheel only has 0 and 1.

  1. Counting means rolling over

    Pick a base and press +1. Watch when a wheel runs out of digits and pushes the next one. That push is called a carry.

  2. Every position has a weight

    In decimal, 345 means 3 hundreds + 4 tens + 5 ones. Each position is worth 10 times the one to its right. In binary each position is worth 2 times the one to its right: 1, 2, 4, 8, 16…

    Treat each bit as a light switch. Turn switches on and add up the weights of the ones that are on.

  3. Hexadecimal is shorthand for binary

    Long rows of 0s and 1s are hard to read. Since 16 = 2⁴, every group of 4 bits becomes exactly one hex digit. Hex needs 16 digits, so after 9 it uses letters: A = 10, B = 11, up to F = 15.

  4. Decimal to binary: keep halving

    Divide by 2 and write down the remainder (0 or 1). Repeat with the quotient until you reach 0. Reading the remainders from bottom to top gives the binary number. For hex, divide by 16 instead.

Common mix-ups
  • "10" is not always ten. (10)₂ is two and (10)₁₆ is sixteen. Always say which base you mean.
  • A to F in hex are digits, not letters. F is just the digit for fifteen.
  • Weights start at 1 on the right, not the left.
  • After dividing, read the remainders from the bottom up.

Memory only stores 0s and 1s. Every kind of data needs a rule for turning it into bits.

Text, negative numbers, decimals, pictures and sound all end up as bits. The computer and the programmer simply agree on a code for each kind of data.

Think of it like

Morse code. Only two signals, short and long, yet you can send any message because everyone shares the same codebook. ASCII, two's complement and IEEE 754 are codebooks for computers.

  1. Text: every character has a number

    The ASCII table gives each character a number from 0 to 127. 'A' is 65, 'B' is 66, 'a' is 97. Unicode extends this to every language and emoji, using more bytes for the extra characters.

  2. Negative numbers: two's complement

    With 3 bits there are only 8 patterns. Two's complement gives half of them to negative numbers. The leftmost bit tells you the sign: 0 means positive, 1 means negative. Picture the patterns arranged on a clock face.

    To make a negative number by hand: write the positive value, flip every bit, then add 1. For −3: 011 → 100 → 101.

  3. Real numbers: scientific notation in base 2

    Scientists write 5250 as 5.25 × 10³. Floats do the same thing in binary: 1.something × 2power. The IEEE format stores three parts: a sign, the power (exponent) and the "something" (mantissa).

  4. Images: a grid of numbers

    A picture is a grid of tiny squares called pixels. In black and white, each pixel is 1 bit. Grayscale uses 8 bits (256 shades). Color uses 24 bits: 8 each for red, green and blue. Click squares to draw.

  5. Sound: many measurements per second

    Sound is a smooth wave. The computer measures its height many times per second; each measurement is a sample. One sample per second is 1 Hz. More samples follow the wave more closely.

  6. How much memory? Count the lockers

    Memory is a long row of lockers, and each locker holds 1 byte (8 bits). Every locker has a number, its address. With n bits for the address you can number 2ⁿ lockers. That's why memory size and address length go together: 2¹⁰ = 1 KB, 2²⁰ = 1 MB, 2³⁰ = 1 GB.

Common mix-ups
  • The character '7' is not the number 7. The character is stored as 55.
  • Some decimals such as 0.1 have no exact binary form, so floats store a very close value instead.
  • Adding 1 to the largest positive number wraps around to the most negative one. This is called overflow.
  • A bit is one 0 or 1. A byte is 8 bits.

A C program names boxes, fills them, and decides what happens next.

Variables are boxes with a type. The type fixes the box size and how its bits are read. Control statements choose which instructions run and how many times.

Think of it like

Cooking from a recipe. Containers have labels and fixed sizes (variables). Steps say "if the sauce is thick, add water" or "stir 10 times" (if and loops). The kitchen has a counter you clean as you go and a storage room you have to tidy yourself (stack and heap).

  1. Every variable is a box of a fixed size

    Whole-number types (char, short, int, long) use two's complement. Decimal types (float, double) use IEEE format. Bigger boxes hold bigger or more precise values.

  2. printf talks, scanf listens

    printf writes to the screen. scanf reads from the keyboard and has to know where to put the value, so you pass the address with &, like giving a delivery address.

    int age;printf("How old are you? ");scanf("%d", &age);     // deliver the number to age's addressprintf("Next year you'll be %d\n", age + 1);

    %d is for int, %f for float, %c for char and %s for text.

  3. Loops: run laps until the condition fails

    A for loop has four parts that run in a fixed order: set up once, check, do the body, update, then check again. Step through to watch the order.

    while checks before each lap. do … while checks after, so its body always runs at least once. switch jumps to a matching case.

  4. Four areas of memory

    Code holds your program's instructions. Data holds global variables. The stack works like a stack of plates: each function call adds a plate for its local variables and removes it automatically on return. The heap is a storage room: malloc rents space and only free gives it back.

Common mix-ups
  • = stores a value and == compares. if (x = 5) is almost always a bug.
  • Leaving out & in scanf makes it write to the wrong place.
  • Dividing two ints drops the fraction: 7 / 2 is 3.
  • A semicolon right after for(...) makes the loop body empty.

A pointer holds an address. It tells you where something lives, not what it is.

Two symbols do all the work. &x means "the address of x". *p means "go to the address in p and use what is there".

Think of it like

A sticky note with a house address written on it. The note is not the house, but you can follow it to the house and change what's inside. You can also have a note that tells you where to find another note.

  1. A variable is a house, a pointer is a note

    After int x = 7; int *p = &x; the house x (at address 0xFA) contains 7, and the note p contains 0xFA. Try each expression.

  2. A pointer to a pointer: a two-step treasure hunt

    int **q = &p; makes q a note that holds the address of the note p. To reach x from q you follow two arrows, which is why it's written **q.

  3. Borrowing memory: malloc and free

    malloc rents a storage unit on the heap and gives you its address. free hands the unit back. Your note still has the old address on it, so set it to NULL to avoid using it by mistake.

Common mix-ups
  • In a declaration, int *p means "p is a pointer". In an expression, *p means "go to that address".
  • A pointer you haven't set could point anywhere. Give it a value before using it.
  • After free(p), p still holds the old address. Using it is undefined behaviour.

Functions get copies. To let a function change your variable, give it the address.

This is the main reason pointers exist. Arrays rely on the same idea: an array's name is the address of its first element.

Think of it like

Lending a photocopy of your notebook versus giving someone your home address. They can scribble on the photocopy all they like and your notebook stays the same. With your address they can walk in and change the real thing.

  1. Copy vs. address

    Both versions try to swap two cups. Choose a version and step through it.

  2. An array is a row of identical lockers

    int a[5] reserves 5 lockers side by side, each the size of an int (4 bytes). a is the address of the first locker. To find a[i], start at a and move i lockers along, so a[i] is the same as *(a + i).

  3. Arrays are always passed by address

    When you pass an array to a function, C passes its address. That's why a function can fill or change your array without any &.

    void doubleAll(int a[], int n) {    for (int i = 0; i < n; i++) a[i] = a[i] * 2;}int nums[3] = {1, 2, 3};doubleAll(nums, 3);   // nums is now {2, 4, 6}

    You can also create an array at run time: int *a = malloc(n * sizeof(int)); and use it the same way, a[0], a[1] and so on. Remember to free(a) afterwards.

Common mix-ups
  • Indexes start at 0. An array of 5 runs from a[0] to a[4], so a[5] is outside it.
  • C does not check array bounds. Going past the end silently reads or writes other memory.
  • Inside a function an array parameter is only a pointer, so sizeof gives the pointer size. Pass the length separately.

Structs bundle related data. Pointers link structs into chains and trees.

A struct groups several fields under one name. Give a struct a field that points to another struct of the same kind and you can build lists and trees that grow while the program runs.

Think of it like

An ID card has a name, an age and a GPA printed on one card: that's a struct. A linked list is a treasure hunt where each clue says where the next clue is hidden. A tree is a choose-your-path game where every stop offers two directions.

  1. A struct is a form with fields

    If you hold the card itself (a variable s), use a dot: s.age. If you only know where the card is (a pointer p), go there first: (*p).age, or the shorter p->age.

  2. A linked list: every cell knows the next one

    Each cell holds a value and the address of the next cell. The last cell holds NULL. You only keep the address of the first cell, called head. To add a cell you don't move anything; you just re-link two pointers.

  3. A binary search tree: smaller left, bigger right

    Each node has a left and a right pointer. Smaller values go left and bigger ones go right. To find a value, compare and pick a side at each node, the way you'd play "higher or lower". Search for a number below.

Common mix-ups
  • p.age with a pointer is an error. *p.age is wrong too, because the dot binds first. Use p->age.
  • If you overwrite head before linking the new cell, you lose the whole list.
  • Forgetting NULL at the end means your loop never knows when to stop.

Files store data as readable characters or as raw bytes. Bitwise operators work on single bits.

A text file writes every value as ASCII characters you could read in Notepad. A binary file copies the exact bytes from memory: two's complement for whole numbers and IEEE for floats.

Think of it like

Writing a number on paper digit by digit, versus photocopying the memory chip that holds it. Bitwise operators are like rows of light switches wired into small circuits.

  1. Same number, two kinds of file

    Type a whole number. The text file stores one byte per digit. The binary file always uses 4 bytes for an int, however many digits the number has.

  2. AND, OR, XOR: tiny circuits

    The operators compare two numbers bit by bit. AND (&) lights a bulb only if both switches are on. OR (|) lights it if either is on. XOR (^) lights it if exactly one is on. NOT (~) flips every bit, and shifts (<<, >>) slide the bits left or right.

  3. Masks: work on one bit

    A mask is a number with a 1 only where you want to act, such as 1 << k. Combine it with OR to turn a bit on, AND-NOT to turn it off, XOR to flip it, or AND to check it.

Common mix-ups
  • & works on bits; && means "and" for true/false conditions. The same goes for | and ||.
  • ^ is XOR, not "to the power of". In C, 2 ^ 3 is 1.
  • Open binary files with "wb" / "rb" and use fwrite / fread. For text, use fprintf / fscanf.
